# 理念

#手册#

对人脑来说，阅读和写作就是 I/O：思考系统与外部世界交流的方式。多数笔记软件只管最后一步，写。但没有读的写是空的，读了没有地方消化的东西，一周后就忘了。

mdSilo 是**个人 I/O 的中枢**。三个环节各有各的工具，再用链接把它们串起来。

```mermaid
flowchart LR
  R["Reading<br/>书、订阅、播客"] -->|高亮| I["Issue<br/>问题、想法、任务"]
  I -->|思考| W["Writing<br/>笔记、wiki、思维导图"]
  W -->|新的问题| R
```

## 1. Reading 是输入

信息从书（EPUB、PDF、MOBI、FB2、CBZ 等）、RSS 和 Atom 订阅、播客、以及你剪藏的网页进来。读到的一切都可以标注：高亮、句子上的笔记、书签。标注是纯 Markdown，放在书的旁边。见 [[5 阅读器|阅读器]] 和 [[6 订阅|订阅]]。

## 2. Issue 是处理

输入是生的。要消化它，需要一个地方放它引出的问题、激发的想法和要做的事。mdSilo 借来了最合适的工具：**issue 追踪器**。一个 issue 是一个思考的单元：有状态（open 或 closed）、标签、里程碑、评论和时间线，还能放到项目看板上。书里的一处高亮、笔记里的一句话、一个复选框，都可以变成 issue。见 [[7 Issue|Issue]]。

## 3. Writing 是输出

最终出来的是文字：笔记、文章、个人 wiki、思维导图、图表。编辑器是所见即所得的，文件却是纯 Markdown，比任何软件都长寿。见 [[3 编辑器|编辑器]]。

## 链接是胶水

三个环节不是一条直线的流水线，而是一个环，**链接**把环合上。笔记可以链接到书（`{{Alice's Adventures in Wonderland}}`）、书里的某一句、某个 issue（`[@1](issue:1)`）和别的笔记（`[[链接]]`）。每条链接都是双向的：被链接的一方知道是谁指向了它。Graph 把整张网画出来，那是你自己建起来的一片星空。见 [[4 链接|链接]] 和 [[8 洞察|洞察]]。

## 原则

- **本地优先。** 数据是你选的文件夹里的文件。没有账号，没有服务器，没有追踪。网页版把文件存在浏览器里，而不是磁盘上。
- **永远是纯文本。** 笔记是 Markdown，批注是 Markdown，issue 是 JSON。用任何工具都能打开，用 git 就能同步。
- **一个工作区，没有孤岛。** 读、想、写共用一套搜索、一份链接索引、一张图。
- **小而快。** 工具应当让路。一切按需加载，索引是增量的。
- **由你塑造。** 主题、字体、斜杠命令、快捷键，以及你自己的目录结构。
